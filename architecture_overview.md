# Davision AI Tech & Trend Radar — Architecture Summary (Supabase Edition)

## Mission
Replace manual AI research monitoring with an autonomous, zero-intervention pipeline that harvests, scores, vectorizes, and delivers technical insights — in Turkish — directly to the team's Telegram channel every 4 hours, backed by a unified Supabase cloud infrastructure.

## The 4-Layer Supabase Architecture

### Layer 1 — Scout Agent
- Three connectors run **concurrently** via `asyncio.gather`.
- **URL Deduplication:** Directly queries Supabase DB using indexing before processing content downstream.
- Lightweight HTML stripping and whitespace normalization applied to raw content.

### Layer 2 — Analyzer Agent (Economic Core + pgvector)

| Tier | Condition | Action | Token Cost | Storage Target |
|------|-----------|--------|-----------|----------------|
| **T0** | Always | Regex keyword match (50+ AI terms) | **0** | Discard |
| **T1** | Passes T0 | GPT-4o-mini relevance score 0–10 | ~150 | Supabase `articles` |
| **T2** | Score ≥ 6.0 | Turkish 3-bullet executive summary | ~300 | Supabase `articles` |
| **T3** | Score ≥ 6.0 | `text-embedding-3-small` (1536d) | ~50 | Supabase `pgvector` |

**Result:** ~93% token savings vs. naïve full-LLM approach. Dual storage (Relational + Vector) handled inside a **single Supabase transaction**.

### Layer 3 — Dispatcher Agent (Supabase Realtime / Webhook Ready)
- Queries `relevance_score >= 7.5 AND is_dispatched = FALSE` via Supabase Client.
- Escapes all **20 Telegram MarkdownV2 special characters** before dispatching.
- `is_dispatched = TRUE` is updated atomically in Supabase **only on confirmed HTTP 200**.
- Exponential backoff retry logic (2s → 8s → 30s, max 3 attempts).

### Layer 4 — Supabase API & Next.js 14
- **FastAPI / Supabase SDK:** Uses Supabase Python SDK for direct connection, database function calls (`RPC`), and vector similarity searches.
- **pgvector Cosine Distance:** Semantic search executes directly via SQL functions inside Supabase (`match_articles`).
- **Next.js 14 Dashboard:** Built-in Supabase Auth & Row Level Security (RLS) to restrict dashboard access to Davision AI team members.

## Key Design Guarantees (Supabase Stack)

| Guarantee | Mechanism |
|-----------|-----------|
| No duplicate articles | `url UNIQUE` constraint + SHA-256 hash in Postgres |
| Vector + Relational Sync | Single Supabase table with `vector(1536)` column (No ChromaDB desync) |
| Native Semantic Search | PostgreSQL `pgvector` index (`HNSW` / `IVFFlat`) |
| No duplicate Telegram sends | Atomic `is_dispatched` update via Supabase Client |
| Complete Access Control | Supabase Row Level Security (RLS) policies |
| Full cost auditability | Every LLM call logged to Supabase `token_logs` table |

## Supabase Database Schema (SQL Definition)

```sql
-- Enable pgvector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- 1. Main Articles Table
CREATE TABLE articles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title TEXT NOT NULL,
    url TEXT UNIQUE NOT NULL,
    author TEXT,
    published_at TIMESTAMPTZ,
    raw_content TEXT,
    summary_bullets JSONB, -- Stores 3-bullet Turkish summary
    relevance_score FLOAT4 DEFAULT 0.0,
    primary_category TEXT,
    tags TEXT[],
    embedding vector(1536), -- OpenAI text-embedding-3-small vector
    is_dispatched BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Index for Fast Semantic Vector Search (HNSW)
CREATE INDEX idx_articles_embedding ON articles 
USING hnsw (embedding vector_cosine_ops);

-- Index for Fast Deduplication & Dispatch Filtering
CREATE INDEX idx_articles_url ON articles(url);
CREATE INDEX idx_articles_dispatch ON articles(relevance_score, is_dispatched);

-- 2. Semantic Search RPC Function
CREATE OR REPLACE FUNCTION match_articles (
  query_embedding vector(1536),
  match_threshold float,
  match_count int
)
RETURNS TABLE (
  id bigint,
  title text,
  url text,
  summary_bullets jsonb,
  relevance_score float4,
  similarity float
)
LANGUAGE sql STABLE
AS $$   SELECT     articles.id,     articles.title,     articles.url,     articles.summary_bullets,     articles.relevance_score,     1 - (articles.embedding <=> query_embedding) AS similarity   FROM articles   WHERE 1 - (articles.embedding <=> query_embedding) > match_threshold   ORDER BY articles.embedding <=> query_embedding   LIMIT match_count; $$;

### Supabase Entegrasyonunun Sağladığı 4 Ana Avantaj

1. **ChromaDB'nin Kaldırılması:** Vektörler doğrudan PostgreSQL tablosundaki `embedding vector(1536)` sütununda saklanır. İlişkisel veri ile vektör verisi hiçbir zaman senkronizasyon kaybı yaşamaz.
2. **Sadeleşmiş Docker Ortamı:** Ayrı bir Postgres, ChromaDB ve Redis konteyneri yönetmek yerine tüm veritabanı yükü Supabase Cloud'a (veya self-hosted Supabase'e) devredilir.
3. **Güvenlik (RLS):** Next.js dashboard'unuza sadece yetkili Davision AI çalışanlarının erişmesini sağlayan `Row Level Security` kurallarını 2 satır SQL ile tanımlayabilirsiniz.
4. **Vektör Arama Fonksiyonu (`RPC`):** Karmaşık SQL veya Python arama kodları yazmak yerine Supabase'in `match_articles` RPC fonksiyonunu çağırarak %100 uyumlu cosine similarity sonuçları alabilirsiniz.
